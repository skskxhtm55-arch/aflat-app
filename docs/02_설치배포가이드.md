# 02. 설치·배포 가이드 (테스트 환경)

이 가이드는 **테스트 환경**을 처음부터 만드는 순서입니다. 운영 중인 스프레드시트·구글폼·룸 캘린더는 전혀 건드리지 않습니다.
실운영 전환은 `04_실운영전환체크리스트.md`를 따르세요.

전체 구조
```
[수강생 휴대폰] ──(앱 화면: GitHub Pages)──▶ [서버: Apps Script 웹앱] ──▶ [스프레드시트] + [룸 캘린더 4개] + [솔라피 알림톡]
   web 폴더                                      server 폴더
```

준비물: 규민 구글 계정(테스트용), GitHub 계정(무료), Windows PC

---

## 1단계. PC에 도구 설치 (최초 1회, 약 15분)
1. **Node.js** 설치: https://nodejs.org → "LTS" 버전 다운로드 → 기본값으로 설치
2. **Git** 설치: https://git-scm.com/download/win → 기본값으로 설치
3. PowerShell을 **새로** 열고 확인 (버전 숫자가 나오면 성공)
   ```bash
   node -v
   ```
   ```bash
   git --version
   ```
4. **clasp** 설치 (Apps Script 코드를 PC에서 올리는 도구)
   ```bash
   npm install -g @google/clasp
   ```
5. Git 사용자 이름 등록 (이력에 남는 이름)
   ```bash
   git config --global user.name "규민"
   ```
   ```bash
   git config --global user.email "본인이메일@example.com"
   ```
6. Apps Script API 켜기: 규민 계정으로 https://script.google.com/home/usersettings 접속 → **Google Apps Script API** 를 **사용**으로

## 2단계. 프로젝트 폴더 옮기기
OneDrive 폴더 안의 Git 저장소는 동기화 중 깨질 수 있어 **OneDrive 밖**으로 옮깁니다.
1. `aflat-app` 폴더 전체를 `C:\dev\aflat-app` 으로 복사
2. PowerShell에서
   ```bash
   cd C:\dev\aflat-app
   ```
   ```bash
   git init -b main
   ```
   ```bash
   git add .
   ```
   ```bash
   git commit -m "1차 개발 초기 버전"
   ```

## 3단계. 테스트용 스프레드시트 + Apps Script 만들기
1. 규민 계정으로 구글 드라이브 → 새 스프레드시트 → 이름 `[테스트] 에이플랫 앱`
2. 메뉴 **확장 프로그램 → Apps Script** → 열린 편집기 왼쪽 **프로젝트 설정(톱니바퀴)**
   - **스크립트 ID** 복사
   - 시간대가 `(GMT+09:00) 서울`인지 확인 (코드를 올리면 자동으로 맞춰짐)
3. `C:\dev\aflat-app\.clasp.test.json` 을 메모장으로 열어 `여기에_테스트_스프레드시트의_스크립트_ID` 를 복사한 ID로 바꾸고 저장

## 4단계. 서버 코드 올리기 (clasp push)
```bash
cd C:\dev\aflat-app
```
```bash
clasp login
```
(브라우저가 열리면 **규민 계정**으로 로그인·허용)
```bash
Copy-Item .clasp.test.json .clasp.json
```
```bash
clasp push
```
- "Manifest file has been updated. Do you want to push and overwrite?" 가 나오면 `y`
- Apps Script 편집기를 새로고침하면 Api.gs, Auth.gs 등 파일이 보입니다.

> 이후 코드를 고칠 때마다: `clasp push` → (6단계의 "새 버전 배포") → `git commit`
> 원장님이 브라우저 편집기에서 직접 고친 경우: 먼저 `clasp pull` 로 받아온 뒤 작업 (수정은 한 곳에서만!)

## 5단계. 스크립트 속성(비밀값) 입력
Apps Script 편집기 → **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**

| 속성 | 테스트 값 | 설명 |
|---|---|---|
| ENV | `test` | **테스트 환경 표시. 실운영에는 넣지 않거나 prod** |
| ALIMTALK_MODE | `off` | 처음에는 off(발송 안 함). 알림톡 시험 때 `test` |
| ALIMTALK_TEST_PHONE | 규민 휴대폰 번호 | test 모드에서 모든 알림톡이 이 번호로만 감 |
| SOLAPI_API_KEY | 현행 코드의 값 | 현행 Apps Script 프로젝트에서 `SOLAPI_API_KEY` 상수 값 |
| SOLAPI_API_SECRET | 현행 코드의 값 | `SOLAPI_API_SECRET` |
| SOLAPI_PFID | 현행 코드의 값 | `PFID` |
| SOLAPI_SENDER | 현행 코드의 값 | `SENDER_NUMBER` |
| TEMPLATE_BOOKING_SUCCESS | 현행 코드의 값 | `TEMPLATE_SUCCESS` (예약 성공 템플릿) |
| TEMPLATE_RESET_REQUEST | (승인 후 입력) | 비밀번호 재설정 요청 알림 템플릿 — `05_알림톡템플릿.md` 참고 |
| ADMIN_PHONE | 원장님 번호 (테스트 중엔 test 모드라 테스트 번호로 감) | H-6 받을 번호 |

- `PASSWORD_PEPPER` 는 첫 로그인 처리 때 **자동 생성**됩니다. **절대 지우거나 바꾸지 마세요** (모든 비밀번호가 무효가 됨).
- 현행 코드의 비밀값(API 키 등)은 현행 프로젝트에서 **복사만** 하고, 현행 프로젝트는 수정하지 마세요.

## 6단계. 시트 구조·테스트 데이터 만들기
1. 스프레드시트 탭을 **새로고침** → 상단에 **에이플랫 관리** 메뉴가 생김 (안 보이면 10초 후 다시 새로고침)
2. **에이플랫 관리 → 설치·테스트 도구 → ① 시트 구조 만들기/점검**
   - 처음 실행 시 권한 승인 창: 계정 선택 → "Google에서 확인하지 않은 앱" → **고급 → (프로젝트 이름)(으)로 이동(안전하지 않음)** → 허용
     (본인이 만든 스크립트라서 나오는 정상 안내입니다)
3. **② 테스트 환경 만들기** → 1~2분 소요
   - 테스트 캘린더 4개(`[에이플랫 테스트] Eb/Bb/F/Db`), 샘플 회원 8명, 내일~글피 샘플 일정, 테스트 계정이 만들어집니다.
   - 마지막 창의 **임시 비밀번호 목록을 메모**하세요 (창을 닫으면 다시 볼 수 없음. 잊으면 메뉴 "임시 비밀번호 발급"으로 재발급)
4. **설치·테스트 도구 → 비밀번호 해시 속도 측정**: 현재 설정(800회, 2026-11-19 실측 반영)이 1,000ms를 크게 넘으면 알려 주세요(반복 횟수 조정).
5. **에이플랫 관리 → 매일 자동 정리 켜기** (만료 로그인 정리)

## 7단계. 서버를 웹앱으로 배포
1. Apps Script 편집기 오른쪽 위 **배포 → 새 배포**
2. 톱니바퀴 → 유형 **웹 앱**
   - 설명: `1차 테스트`
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
3. **배포** → 표시되는 **웹 앱 URL**(…/exec) 복사
4. 확인: 그 URL을 브라우저 주소창에 붙여넣으면 `"에이플랫 API 서버가 동작 중입니다."` 가 보여야 합니다.

> **코드를 고친 뒤에는** `clasp push` 만으로는 앱에 반영되지 않습니다.
> **배포 → 배포 관리 → (연필) 편집 → 버전: 새 버전 → 배포** 를 해야 같은 URL에 새 코드가 적용됩니다.
> ("새 배포"를 누르면 URL이 바뀌니 주의)

## 8단계. 앱 화면에 서버 주소 넣기
`C:\dev\aflat-app\web\config.js` 를 메모장으로 열어
```js
API_URL: 'https://script.google.com/macros/s/여기에_배포_ID를_붙여넣으세요/exec',
```
의 주소를 7단계 URL로 바꾸고 저장 → 커밋
```bash
git add .
```
```bash
git commit -m "테스트 서버 주소 설정"
```

## 9단계. GitHub Pages로 앱 화면 배포
1. https://github.com → 오른쪽 위 **+ → New repository**
   - 이름: `aflat-app`, **Public** (무료 Pages는 공개 저장소 필요. 비밀값은 저장소에 없으므로 안전)
   - 다른 옵션은 체크하지 않고 **Create repository**
2. PowerShell에서 (주소는 화면에 나온 본인 저장소 주소)
   ```bash
   git remote add origin https://github.com/본인아이디/aflat-app.git
   ```
   ```bash
   git push -u origin main
   ```
3. 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions**
4. 저장소 **Actions** 탭에서 "화면 배포 (GitHub Pages)" 실행 → 초록 체크가 되면 완료 (처음 1회는 Actions 탭에서 **Run workflow** 를 눌러야 할 수 있음)
5. 앱 주소: `https://본인아이디.github.io/aflat-app/`
6. 휴대폰으로 접속 → 테스트 계정으로 로그인 → `03_테스트시나리오.md` 진행

```bash
cd C:\dev\aflat-app
```
```bash
npx http-server -p 8080 -c-1
```

- 끝내려면 PowerShell에서 Ctrl+C

## 자주 겪는 문제
| 증상 | 원인·해결 |
|---|---|
| 앱에 "config.js 에 서버 주소가 설정되지 않았습니다" | 8단계 미완료 |
| 앱에 "인터넷 연결을 확인해 주세요" | 웹앱 URL 오타, 또는 7단계에서 액세스를 "모든 사용자"로 안 함 |
| 코드를 고쳤는데 앱에 반영 안 됨 | 7단계 박스: "배포 관리 → 새 버전" 필요 |
| 화면 파일을 고쳤는데 휴대폰에 옛 화면 | 1~2분 기다린 뒤 앱을 완전히 닫았다 다시 열기 |
| "'회원' 시트가 없습니다" | 6단계 ① 실행 |
| "운영설정 값이 올바르지 않습니다" | 운영설정 시트의 해당 항목 값 확인 |
| clasp push 시 "User has not enabled the Apps Script API" | 1단계 6번 |
