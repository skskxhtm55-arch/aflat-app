# 04. 실운영 전환 체크리스트

원칙
- **현행 스프레드시트·구글폼·현행 Apps Script는 수정하지 않고 그대로 둡니다.** 실운영용 스프레드시트를 새로 만들고, 현행 'Key' 시트는 읽기만 해서 가져옵니다.
- **룸 캘린더 4개는 현행 그대로 함께 씁니다.** 앱과 현행 폼 시스템이 같은 제목 규칙을 쓰므로 기존 예약을 옮길 필요가 없습니다. 언제든 되돌릴 수 있습니다.
- 실운영 서버는 **은솔 원장님 계정**이 소유·배포합니다. 캘린더 쓰기 권한이 원장님 계정에 있고, 웹앱은 배포한 사람 권한으로 실행되기 때문입니다.

---

## A. 사전 준비 (전환 1~2주 전)
- [ ] **A-1. 알림톡 템플릿 신청**: 비밀번호 재설정 요청 알림(H-6) 템플릿을 솔라피에서 신청 (`05_알림톡템플릿.md`). 승인까지 수일 걸릴 수 있음
- [ ] **A-2. 실운영 스프레드시트 생성** (은솔 계정): 새 스프레드시트 `에이플랫 앱 (운영)`
  - 규민 계정을 **편집자**로 공유 (코드 올리기용)
- [ ] **A-3. 코드 올리기** (규민 PC)
  - 실운영 시트 → 확장 프로그램 → Apps Script → 프로젝트 설정 → 스크립트 ID 복사 → `.clasp.prod.json` 에 입력
  - 규민 계정이 이 프로젝트 편집자인지 확인 후
    ```bash
    Copy-Item .clasp.prod.json .clasp.json
    ```
    ```bash
    clasp push
    ```
  - 작업이 끝나면 다시 테스트로 돌려놓기: `Copy-Item .clasp.test.json .clasp.json`
- [ ] **A-4. 스크립트 속성** (은솔 계정으로 편집기에서 입력)
  | 속성 | 값 |
  |---|---|
  | ENV | `prod` (**test 로 쓰면 안 됨**) |
  | ALIMTALK_MODE | 리허설 동안 `test`, 전환 당일 `live` |
  | ALIMTALK_TEST_PHONE | 리허설 때 받을 번호 |
  | SOLAPI_API_KEY / SOLAPI_API_SECRET / SOLAPI_PFID / SOLAPI_SENDER | 현행과 동일 |
  | TEMPLATE_BOOKING_SUCCESS | 현행 성공 템플릿 ID |
  | TEMPLATE_RESET_REQUEST | A-1 승인된 템플릿 ID |
  | ADMIN_PHONE | 원장님 번호 |
- [ ] **A-5. 시트 구조 만들기**: 실운영 시트 새로고침 → 에이플랫 관리 → 설치·테스트 도구 → ① 시트 구조 만들기/점검 (권한 승인은 **은솔 계정**으로)
- [ ] **A-6. 기존 데이터 가져오기**: 설치·테스트 도구 → **기존 Key 시트에서 데이터 가져오기** → 현행 스프레드시트 주소 붙여넣기
  - 룸: Key A~D열 → 룸 시트 (캘린더 ID 그대로 = 실제 룸 캘린더)
  - 수강생: Key F(이름)·G(수강생 번호)·H(악기)·K(연락처) → 회원 시트, 로그인ID = 연락처
  - 끝나고 나오는 **[확인 필요]** 목록을 하나씩 처리
- [ ] **A-7. 회원 시트 정리** (원장님)
  - [ ] 원장님 본인 줄 추가: 역할 `원장`, 로그인ID = 원장님 휴대폰 (수강생번호는 비워도 됨)
  - [ ] 강사 줄 추가(필요 시): 역할 `강사`, 예약하려면 수강생번호(예: TCH001)·등록악기 입력
  - [ ] 휴원·퇴원생 상태를 `휴원` / `종료`로
  - [ ] 형제가 학부모 번호를 함께 쓰면 로그인ID를 같은 번호로 (자동으로 계정 1개)
  - [ ] 이름에 `_` 없는지, 등록악기가 `;`로 구분되어 있는지
  - [ ] **등록악기 글자 = 룸 시트 허용악기 글자** 인지 (예: "피아노" vs "피아노 " 공백 주의)
- [ ] **A-8. 룸 시트 확인**: 이름(Eb/Bb/F/Db), 표시순서, 허용악기(`;`), 배정우선순위가 현행과 같은지
- [ ] **A-9. 운영설정 확인**: 기본값이 현행 규칙과 같음(08:00~24:00, 7일, 120분, 30/60/90/120, 분할 30·15·60)
- [ ] **A-10. 원장 계정 발급**: 에이플랫 관리 → **임시 비밀번호 발급** → 원장님 번호 → 앱 로그인 → 10자 이상 비밀번호로 변경
- [ ] **A-11. 웹앱 배포** (반드시 **은솔 계정**으로): 배포 → 새 배포 → 웹 앱 / 실행: 나 / 액세스: 모든 사용자 → URL 메모
  - 이후 코드 수정 반영(배포 관리 → 새 버전)도 은솔 계정으로 하는 것을 권장합니다 [추정: 다른 사람이 배포를 수정하면 실행 계정이 바뀔 수 있음]
- [ ] **A-12. 매일 자동 정리 켜기** (은솔 계정)
- [ ] **A-13. 리허설** (ALIMTALK_MODE = test)
  - [ ] `web/config.js` 의 `TEST_API_URL` 에 A-11 URL을 **임시로** 넣고 배포 → 앱 주소 끝에 `?test=1` 로 접속
  - [ ] 원장 계정으로 시간표가 현행 연습실 현황 페이지와 같은지 비교 (같은 날짜, 같은 "마감" 칸)
  - [ ] 리허설용 회원 1명 추가: 관리 → 회원 등록 (이름 `리허설`, 로그인ID = **원장님 번호**, 수강생번호 `TEST999`, 등록악기 `피아노`) → 원장 계정에 자동 연결되어 원장 계정으로 예약 가능 → 이용이 적은 시간(예: 6일 뒤 23:00)에 30분 예약 → 실제 룸 캘린더에 정상 제목으로 등록되는지 확인 → **캘린더에서 바로 삭제**, 회원 시트에서 상태 `종료`
  - [ ] 알림로그 '성공 (test 모드)' 확인
  - [ ] 확인 후 `TEST_API_URL` 을 다시 테스트 서버 주소로 되돌림
- [ ] **A-14. 수강생 계정 일괄 발급**: 원장 계정 → 관리 → **계정 없는 회원 N명 일괄 발급** (30명씩) → 안내문을 복사해 **보관만** (아직 보내지 않음)
  - 임시 비밀번호는 7일 유효 → 전환일 7일 이내에 발급하세요. 지나면 해당 회원만 재발급

## B. 전환 당일
- [ ] **B-1.** `web/config.js` 의 `API_URL` 을 실운영 URL(A-11)로, `TEST_API_URL` 을 테스트 서버 URL로 → 커밋 → `git push` → Actions 완료 확인
- [ ] **B-2.** 앱 접속 → 원장 계정으로 시간표·관리 화면 확인
- [ ] **B-3.** 스크립트 속성 `ALIMTALK_MODE` = `live`
- [ ] **B-4. 기존 구글폼 응답 중지**: 구글폼 편집 → **응답** 탭 → **응답 받기** 끄기 → "응답 받지 않음 메시지"에 안내 입력
  > 연습실 예약은 이제 에이플랫 앱에서 해 주세요: (앱 주소)
  - 폼·현행 Apps Script·트리거는 **삭제하지 않습니다** (되돌리기용)
- [ ] **B-5.** 수강생 안내 발송 (A-14 안내문 + 홈 화면 추가 방법)
- [ ] **B-6.** 현행 연습실 현황 페이지(Index.html 웹앱)는 그대로 두어도 됩니다(조회만 함). 페이지의 "예약하러 가기" 버튼은 닫힌 폼으로 연결되므로, 폼의 응답 중지 메시지에 앱 주소가 꼭 있어야 합니다.

## C. 전환 후 1~2주 점검
- [ ] 매일 **예약로그**에서 '실패'와 사유 확인 (규칙과 다른 거부가 있는지)
- [ ] **알림로그**에서 '실패' 확인
- [ ] **재설정요청** 시트에 '접수'가 남아 있지 않은지
- [ ] Apps Script 편집기 → **실행** 메뉴에서 오류(빨간색) 확인
- [ ] 레슨 일정 제목을 `(레슨)방이름_수강생명_악기_수강생번호` 규칙으로 바꾸기 (2차 "레슨 일정 조회" 준비. 1차 동작에는 영향 없음)

## D. 되돌리기 (앱에 문제가 생겼을 때, 5분 이내)
1. 실운영 스크립트 속성 `MAINTENANCE_MESSAGE` 추가, 값 예:
   > 앱 점검 중입니다. 당분간 기존 예약 폼을 이용해 주세요: (폼 주소)
   → 앱의 모든 화면에 이 문구가 표시되고 예약이 막힙니다.
2. 구글폼 **응답 받기** 다시 켜기 → 현행 시스템이 그대로 동작
   - 앱으로 만든 예약은 이미 룸 캘린더에 같은 제목 규칙으로 있으므로, 현행 시스템도 그 예약을 인식합니다(시간 중복·1일 한도).
3. `ALIMTALK_MODE` = `off` (선택)
4. 문제 해결 후: `MAINTENANCE_MESSAGE` 삭제 → 폼 응답 다시 중지

## E. 안정화 후 정리 (전환 2주 이상 문제 없을 때)
- [ ] 구글폼은 **응답 중지 상태로 보존** (삭제 권장하지 않음)
- [ ] 현행 Apps Script의 폼 제출 트리거는 남겨도 무방 (폼이 닫혀 실행되지 않음)
- [ ] 현행 Code.gs 에 있던 솔라피 키는 실운영 스크립트 속성으로 옮겨졌으므로, 새로 키를 발급해 교체하고 싶다면 실운영 스크립트 속성만 바꾸면 됨
